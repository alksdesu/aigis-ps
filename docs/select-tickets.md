# 单位自选券

Type20邮件已接入入箱、选择、发卡和持久重试。当前SelectTicketConfig有223组、19,003条候选，包含1,025种不同的角色、等级及进化组合。所有组合均可按当前原生初始化规则解析，含Level50及强制初始阶段2的角色。

## 配置与领取

邮件内部以`SelectionConfigID`保存选择配置号，42响应对应PPT.A4。发放接口为`PresentService.enqueue`的`kind=selection_ticket, config_id, count, description`。多张券拆为独立Content1邮件，每封只选一个角色。既有Content大于1的自选券可读取，领取被拒，用控制台的`presents.split_ticket_mail`拆成逐张邮件后照常领取，避免无依据地消费整封。

原生请求复用注册1/2，在同一RT/PT2中提交三个整数：PresentID、SelectID、SelectCardID。SelectID是该配置的1基候选序号，SelectCardID必须等于该位置的角色ID。序号按资源组原始顺序分配，界面排序或筛选不重新编号；临时预览使用的UX+2000不会保存为角色身份。

服务器依据实际未领取邮件确定配置，核对序号和角色，检查全部容量与战斗预留，再生成一个新实例。等级、职业、技能及经验由该候选的资源与共享原生初始化器决定。相同角色可得到新实例，保留原有角色成长。成功回SYSTEM、PBP.UX和一行完整21字段PPU，后续42返回已删除该券的完整邮箱。

自选字段只允许用于真实自选券。普通物品、Type16随机券及Type22道具券不会忽略这些字段后继续领取。1/2多个邮件混领、错位序号、其他配置的角色及未知配置都会拒绝，保留原邮件。117批领只提交PresentID，会跳过自选券并保留邮件，其余邮件照常领取；带自选字段的117按非法请求拒绝。原生批领列表是否会带上自选券仍未证实，跳过属于本地政策。

## 存档与更新

`select_ticket_history`保存最多16份回执和最近256个已处理请求摘要，按完整请求识别，不依赖客户端CT；回执被淘汰后重发的旧包返回`select_ticket_request_stale`并记录警告。发卡、删除邮件、分配身份和写回执在同一CAS中完成；重试须匹配完整请求、配置、所选候选、当前修订版与新增实例，后续状态变化则旧回包过期。并发中若邮件内容改变，原请求中止。

目录保存完整候选顺序，指纹包含SelectTicketConfig、OnCommand及CardData。当前候选没有额外评级脚本。未来某组出现未核实的非空评级表达式时，该组暂停新发放和领取，旧邮件仍可读取；其他组保留功能。不会删掉受限候选后重排索引。

`UnitGrants`统一自选券与随机券的初始字段和完整状态校验。目录初始化按不同组合一次批量校验，共用冻结的数据；只在批次边界重查版本。实际发卡仍检查容量、身份上限、版本和完整返回结果，避免逐候选重复读取同一份资源。
