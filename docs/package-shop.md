# 本地礼包与高级通行证

本地复刻使用客户端已有的免费礼包流程：46读取目录，50提交SKU并领取，47刷新目录和购买记录。只有启用`--event-pass-revival`时才开放对应的本地高级通行证礼包；没有配置复刻时目录为空。

另已加入独立可选的Type2日奖礼包，见`purchased-login-rewards.md`。启用时两类商品共享46/47/50入口和完整PPF；高级资格仍直接入库存，日奖购买只建立资格，不提前发放每日奖励。二者的开关和记录相互独立。

## 商品与领取规则

当前商品来自资源已有的六组普通/高级通行证对应关系。只有状态为1、且处于购买窗口的组出现在目录中。礼包价格固定为0，直接取得一份对应高级资格物品，不扣结晶、不增加结晶月消费，也不调用平台支付。

每种普通通行证终身领取一次。更改复刻时间、展示文字或商品编号不会重置次数；旧档已有资格只建立兼容基线，不再次发放。EP余额和两个轨道的已领奖水位均保持原值。取得资格后，通过159领取已经达到积分要求的高级档奖励。

商品标识使用`2_000_000_000 + 该组首条RewardID`，SKU使用`local_`加高级物品名。它们是本地标识，不是官服SKU。原始资源只提供奖励身份和显示素材，不包含当前官服完整礼包调度，因此这些商品不代表官服所有礼包已还原。SKU经PSC.SkuID这一原生行表单元格下发，超过255个UTF-8字节会被客户端截断，50永远匹配不到；这类通行证不列为商品，status的excluded_offers写明通行证、物品名、字节数与上限。当前资源的SKU均为33字节，没有被排除的商品。

## 原生契约

PSC为完整商品目录。`PackageDisplayScene=2`对应新礼包页，物品使用`PackageItemType=9`、实际`ItemID`和数量1。`Price=0`使`PurchaseCommonPackage`调用原生50，正价DGP流程所用91/154不会被调用。

目录保留完整的原生列，包括值为0的货币和单位字段，以及同时扩展父、子记录至第34槽的WidgetID。原生数值读取器会解引用缺失槽位，不能删掉这些看似没有效果的列。按钮引用已验证的通用礼包模板资源4203149，不用空编号占位。

PPF同样返回完整快照。`PPF.PackageID`对应的是`PSC.PackageFlag`，其`PurchaseFlag`是已购次数，不能当作是否允许购买的布尔开关。剩余次数由客户端用`PackageRepeatCount - PurchaseFlag`计算。本地商品两个标识取相同数值，但目录和服务仍分别保存字段。

购买窗口采用原生的`start <= now < end`，结束时刻不包含在内。PSC的OpenDays/CloseDays为原生日期字符串；PPF的PurchaseStartDateTime/PurchaseEndDateTime为从公元1年起的带日内小数的D类型日数，不使用Unix秒或字符串。

50响应返回SYSTEM、完整PPF、受影响的POSSESSION和空PSR。非空POSSESSION恒带Enabled（缺省行为0）；存档中只有两列的旧回执重放时先按三列、再按旧两列规则重建比对，任一与存档字节相同即原样返回。高级物品直接入库存；空PSR清除旧礼包的演出队列。47也清除该队列，46不提供未注册的PSR组。此商品不生成付费结晶、抽选结果或单位奖励。

## 独立文案与资源版本

名称、说明及确认文案明确写明本地免费礼包。`cfgImplantText.atb`和`SystemText.atb`追加独立行，原有官服文案和共享引用保持原样。SystemText按物理行序号读取，不能任意指定一个很大的TextID；覆盖生成器使用实际追加位置，并校验全部引用。

本地文本与复刻、邮件模板覆盖一起生成有效资源索引。服务端与独立客户端准备程序读取同一套资源；文本行位置变化会产生新的资源版本，不改变玩家的购买身份。资源版本变化在控制台属content档切换，需要关闭客户端并重新准备客户端资源；控制台的`events.packages`视图只读列出`package_purchases`中的资格记录。

## 存档与事务

`package_purchases`按普通通行证记录资格身份、次数、来源和请求摘要。`package_history`保留16条请求回执及最多256个已处理请求摘要，不再以客户端CT为水位；回执淘汰后的同包按已处理拒绝（409 package_request_stale，记WARNING）。版本1回执由共享账本升级时把包身份字段归入identity，可原样重放。新资格的普通通行证ID与物品ID须在255字节原生单元内，否则拒绝（503 package_identity_unreplayable，记WARNING）；已存的256字节旧记录照常读取。`package_delivery`独立记录最后一次实际发放。取得资格与这些记录共用一次存档提交。50号礼包回执提交之后，礼物箱的可选依赖或称号目录才接入时，高级通行证礼包与日奖礼包的旧回执都按原字节重放：服务端按日奖服务在各礼物箱配置下的内容指纹（`content_version_for`）逐个重算礼包摘要比对；不含日奖分节的旧布局摘要（日奖礼包接入之前）只适用于没有`kind`的高级礼包回执。伪造的摘要，或嵌入了任何礼物箱配置都不会产生的日奖指纹，仍回409 `package_retry_stale`。礼包摘要经礼包目录也含通行证目录内容版本。通行证窗口按JST时刻比较时提交的回执，其礼包目录摘要所含的通行证目录版本按旧规则名`status_1_and_inclusive_start_end_jst`求值；与当前日奖指纹或日奖服务任一可达礼物箱指纹组合后，照常逐字节重放。旧窗口下日奖礼包接入之前提交的高级礼包回执同样重放，并按当时不含日奖行的PPF重建比对。日奖礼包回执若声称不含日奖分节，或嵌入了任何礼物箱配置都不会产生的日奖指纹，旧窗口下同样回409 `package_retry_stale`。

领取前验证SKU、窗口和限购，提交前核对46/47/50响应与129/137库存回读。任何检查或编码失败都不发物品。并发冲突重新读取存档，精确重放核对实际库存、购买来源和原始响应，不再次发放，也不重新使用当前窗口判定已成功的交易。

## 尚未覆盖

原生窗口尚未验收，当前仅后台实现与定向测试。官服礼包调度以及抽卡、单位等其它礼包形状仍未接入本地商店，登录奖励只有本地的购买后每日领奖礼包（见`purchased-login-rewards.md`）；不能用本地高级资格已接通来宣称整个礼包商店完成。列表采用现有通用礼包模板，未设置额外横幅；详情使用高级通行证物品本身的图标。
