# 技能与显示设置

注册10使用`PU.A7/B0/SC`三个整数，分别是现有角色GetIndex、显示类型和技能切换差异。SC=1表示切换一次，不能当成绝对的“启用觉醒技能”；SC=0仅保存显示。该接口不消耗物品或货币。

普通技能与觉醒技能来自持久原CardID，不取图像替换卡。切换只改变AE的bit2和AD；B1、技能等级、技能经验、好感、锁定、编队和兵营标志保持原值。原生旧状态B1=0但AE含觉醒位时也允许切回普通，本地不擅自把B1修成1。两者都没有时不能通过此接口首次觉醒。

回应包含SYSTEM及目标完整21字段PPU，防止已有单位接收器把缺列写成零。目标在第二/第三兵营时PPU为零行：该接收器只在第一兵营按GetIndex定位，找不到会改写第一兵营最后一个单位。内容策略为2，修复前回执重试按过期处理。独立`unit_detail_history`保存16条回执与最近256个已处理请求摘要（CT不作排序，旧版水位历史读取时自动升级）；精确重试不再次切换，已有后续写入则拒绝旧响应，CAS冲突会重新核对当前状态。服装目录在回执提交之后才接入时，回执摘要按无服装目录计算仍算一致，旧回执原样重放；服装目录内容变化或被移除时按过期处理（409 `unit_detail_retry_stale`）。培养目录的可选仓库输入（妖精乡、可写的银之馆，以及妖精乡的额外兵营容量）后接入时，回执按培养目录的可达版本核对，同样原样重放，并可与服装目录后接入组合；培养目录的其他内容变化或伪造摘要仍按过期处理。无变化的SC0也只记录一次回执。

## 可保存的显示

旧B0值可保持，0为默认。新的基础1/2/3分别核对原卡头像、觉醒阶段和对应二觉头像；阶段4的二觉头像仍用B0=3，不把B0当作职业阶段。手机差分17/18/19同时要求相应基础头像及手机图片存在。

手机图片开关来自OnSystemCommand的UseSmartPhoneImage命令。当前PC平台标签为DMM/R18/WIN/DGP，实际命令`IsPlatForm("DMM");`生效；缺命令、空命令及不支持的表达式分别按已核实规则处理，不执行任意脚本。

额外服装由原卡ExtendSkin01..04关联SkinPackage。免费条件成立，或对应POSSESSION物品持有量为正，才允许新选B0=5..8；可用手机差分再加16。每次读取当前物品状态，保存显示不扣道具。图像替换卡的服装不会自动授予原卡。

当前47个服装定义、103条角色关联中，7条免费关联已验证。新版`get_skin_00046`和`get_skin_00047`已有Stack0定义；已持有库存时可识别对应外观解锁，没有库存时保持锁定，不能通过邮件或商店新增库存。既有显示值仍保留，不能仅因定义变化删除旧存档设置。

控制台`units.set_display`按GetIndex与UniqueID定位单位，对不上时返回409 `admin_unit_display_missing`；它调用与10相同的绝对显示内核`UnitDetailService.set_display`，头像、手机差分与服装校验相同，失败码也与10一致（如501 `unit_detail_display_unsupported`）。只改B0，不提供SC相对切换，不写`unit_detail_history`，提交后回读41。
