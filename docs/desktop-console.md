# 桌面控制台

`AigisConsole.exe`在独立的Windows WebView2窗口中嵌入管理界面，负责选择存档、启动和停止本地服务、启动已准备的游戏副本。打开窗口本身不会启动游戏服务。现有存档编辑、配置、备份、恢复和审计继续使用[管理控制台](admin-console.md)的API和检查。

## 安装与打开

项目提供公共主表、资源索引和小型固定启动资源；游戏本体与大资源由玩家按[首次安装说明](../README.md)下载并准备本地副本，不随GitHub仓库分发。在本机安装Python和WebView2后，在项目目录执行：

```powershell
.\setup.ps1 -IncludeDesktop
.\start-console.ps1 -Check
```

需要Python 3.12或更新版本、项目`.venv`和Windows WebView2 Runtime。`setup.ps1 -IncludeDesktop`在本机安装桌面Python依赖。源码不包含生成的`AigisConsole.exe`；需要双击入口时运行`.\build-console.ps1`，也可直接用`.\open-console.ps1`打开同一个独立窗口。启动器依赖项目解释器与源码，不能单独移走运行。普通玩家无需安装采集依赖或自行采集主表，维护者资料准备见[发布说明](release-preparation.md)。

日常双击`AigisConsole.exe`，或运行`.\open-console.ps1`、`.\start-console.ps1`。`-Check`只导入并检查桌面依赖，不启动服务、不打开玩家存档；它不能替代游戏副本和服务启动闸门的检查。

`open-console.ps1 -Browser`保留原有Edge入口，用于连接已经由`start-server.ps1`启动的管理服务。`-PrintUrl`只打印已有服务的地址。桌面应用不需要Edge浏览器窗口，使用自己的WebView2宿主。

## 启动与切换存档

全新安装应先按[玩家教程](../README.md)下载支持版本的原版游戏、核对客户端指纹、安装环境，使用项目提供的主表和索引补齐大资源，再准备本地副本。玩家不需要采集或导入主表；配套公共资料缺失时应恢复同版本项目文件。更新时先看[更新记录](../changelog.md)中的支持版本与存档要求，已有独立档不会随公共资料更新自动迁移。

1. 在「启动与存档」核对当前存档名称与数据目录。全新安装尚无存档时，先输入名称并点击「创建第一份存档」；创建成功后自动选中，再进行下一步。
2. 点击「启动服务」，等待状态变成「运行中」。启动期间可点「取消启动」，取消后需等待资源初始化收尾；其他启动操作保持禁用，失败原因和日志路径显示在同一页。
3. 点击「启动游戏」。启动前仍会验证已准备的`runtime/client`副本及服务状态，校验在后台执行。
4. 结束游玩或准备切档时，先从游戏中退出，再点击「停止服务」，等待停止完成。
5. 选择另一份存档，然后重新启动服务与游戏。

应用不会替用户强行关闭正在运行的游戏。游戏仍运行或正在启动时，停止服务、新建和切换存档均被阻止。独立命令行启动的服务若占用游戏端口18103，也必须先停止。

启动失败时，界面分别提示数据库日志或占用、缺少能量时钟标记、存档校验失败等原因。遇到旧档的数据库日志提示，可以关闭相关程序后检查旧档，也可以新建并选择独立存档继续使用。只有缺少能量时钟标记时才提示确认来源时区并迁移；未知错误仍通过本次启动日志排查。

服务未运行时，可在「启动与存档」页管理启动和存档选择，其他存档管理页提示先启动服务，不发送存档API请求。换档或服务状态变化会取消旧存档页面请求、关闭旧确认框并重建页面。转发存档请求还携带所选档ID，宿主拒绝与当前档不符的请求。

## 新建独立存档

全新项目首次打开不会自动创建或登记默认档。无存档时页面显示首次创建提示，启动服务和启动游戏按钮不可用。输入名称并点击「创建第一份存档」后，第一份存档自动选中，但不自动开服。

已有存档时，在服务和游戏均已停止后输入名称，点击「新建独立存档」。名称需为1至64个可打印字符，去掉首尾空白后不能与已有名称重复。后续新建完成后原档仍保持选中，需要在列表中点击新档的「切换到此存档」。

第一份存档从`runtime/server`复制并校验随包准备的公共主表和可选生效配置；后续新档从当前所选档复制这些公共资料。公共资料缺失或校验失败时明确报错，不登记残缺存档。不会复制`aigis.sqlite3`、角色、任务进度、奖励记录、备份或审计记录，也不会复制待应用的暂存配置。新玩家数据库在首次启动该档的服务时按现有初始化规则生成。

已有`profiles.json`时保留全部条目和当前选择。旧版项目没有该文件、但已有非空的普通玩家数据库时，才将`runtime/server`登记为“当前存档”；识别过程只检查文件属性，不打开数据库。只有公共主表而没有数据库的目录不会被当作已有玩家存档。不要删除登记文件来重置首次使用状态。

资源库`runtime/resources`与准备好的游戏副本`runtime/client`共用；各档的玩家数据库、配置、主表指针和备份放在各自数据目录。更换存档无需再次复制完整游戏资源。新建存档不是备份或恢复；需要保留某个玩家的完整进度时，使用管理控制台的备份与恢复功能。

## 文件与日志

| 位置 | 用途 |
|---|---|
| `runtime/server` | 首档的公共资料来源；旧版项目也可能在此保存已有玩家数据 |
| `runtime/saves/<ID>` | 新建存档的独立数据目录 |
| `runtime/desktop/profiles.json` | 存档列表和当前选择；首次可为空 |
| `runtime/desktop/webview` | 桌面WebView2配置与缓存 |
| `runtime/desktop/desktop.log` | 桌面宿主日志 |
| `runtime/desktop/launcher.log` | EXE启动器收集的进程输出 |
| `runtime/desktop/server-<时间>-<ID>.log` | 启动服务后生成的日志，启动页显示实际路径 |

尚未启动过服务时，启动页的日志文件显示「尚未生成」。只打开桌面窗口不会创建或初始化玩家数据库。关闭窗口时会停止该窗口管理的服务；若游戏仍在运行或服务未能结束，窗口保留并提示原因。

## 实现边界

桌面宿主在动态回环端口提供界面与启动管理API，使用独立的本次启动令牌；管理请求转发到当前服务，不暴露服务令牌给页面。宿主不提供任意命令执行或任意文件路径入口。页面令牌只保存在内存，WebView2缓存中不主动持久化令牌。

`desktop.py`管理窗口与宿主生命周期，`desktop_controller.py`管理服务和游戏状态，`desktop_profiles.py`管理存档目录与公共配置复制，`desktop_api.py`提供受限启动API与管理代理。`desktop_worker.py`运行服务并接收停止指令；`desktop_processes.py`识别相关游戏进程。启动页源码是`admin_ui/desktop-page.js`，宿主单独发布该页，不加入传统服务的页面发现目录。

桌面窗口、隔离存档和管理界面的验证不代表原生游戏流程已实测通过。服务与玩法的实现范围、原生客户端验证进度仍以[项目说明](../README.md)和[实现记录](implementation.md)为准。
