# 战神加护与服装取得

基础邮件目录支持116项普通库存物品、242项战神加护和38项服装解锁道具，共396项；启用已验证的83项称号目录后共479项，见emblems.md。此处的加护和服装按资源校验Category、Stack=1、CanAllGet=0、NoAutoDelete=1及普通领取流程；称号的NoAutoDelete为0，使用独立规则，不能因同为唯一物品就混用。

## 邮件领取

新增两类仅允许通过1/2逐封领取，1/2多封混领整体拒绝；117批领跳过它们并保留邮件，其余邮件照常领取，只选了这类邮件时回空成功、不写回执。原有普通物品的按请求顺序部分领取，以及恢复料理的独立单领规则保持不变。已持有唯一道具时，重复邮件保留，库存和任务不增加。

领取仅增加POSSESSION.Count并删除成功邮件，保留已有Enabled设置，沿用42、129、137回读及原生编码预检。失败、并发冲突和旧请求重放不会造成重复发放。邮件结构、角色实例和现有余额不迁移。

## 服装与任务

持有解锁道具后，原有UnitSkinCatalog允许对应外观；领取不直接替换角色当前外观，不要求账号已经拥有适用角色。计数依据SkinPackage的Aggregate包，而不是关联角色数或槽位数。当前38个可授予聚合包与38个道具一一对应；新版46/47已有Stack0物品定义，只支持识别已有库存解锁，不纳入邮件发放或购买。未来出现聚合免费包或多个包共用道具时先拒绝未知计数规则。

成功领取服装时，同一事务记录Type11进度及skin_acquisition_history。历史保存已见过的道具，重复取得和删除后恢复不重复计数。已存历史按旧的256字节物品名上限读取，按旧上限保存的存档照常加载并继续累加；服装目录道具及新的取得事件仍须在255字节原生单元格内。历史不下发给客户端，这只是本地存档兼容；当前服装道具名最长14字节。首次遇到旧档时把已持有服装作为基线，不追补过去任务；原生列表的显示分子来自当前全部持有包，因此旧档显示总数可以高于从接入后累计的任务进度。这是保留既定旧档政策的本地区别，新档从零取得时两者一致。

任务服务或服装目录缺失时，服装领取明确失败并保留邮件；不能先领到道具再漏掉计数。普通道具和战神加护不因缺少服装目录被一并禁用。独立SkinShop现已调用MissionService.record_acquisitions复用相同事务逻辑；后续控制台发放也不能只修改库存。

## 加护效果边界

战神加护属于持有后可开关、带职业或编队条件的效果，不是限时经验/金币加成。已确认POSSESSION.Enabled缺列时原生读取为0。领取及购买不自动开启；148现已接入独立设置，见blessing-settings.md。

SaveBattleGodBlessSettings和Enabled存储已接通，所有库存消费方共享保留开关的加减方法。加护战斗条件和效果验收保留在后续战斗阶段。本批没有启动游戏、服务或修改正式存档。

当前382条任务奖励中355条可生成邮件，剩余27条为残缺池召唤券；这里描述奖励格式兼容性，不代表所有任务完成条件均已接通。完整428池的11条任务券走独立Type22抽取流程，不计入普通库存物品，见item-summon-tickets.md。独立服装商店156及名声殿堂已接通，见skin-shop.md、fame.md；活动仍待后续实现。
