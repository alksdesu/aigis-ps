# 官服响应通用采集

`client/capture-responses.ps1` 附加原版 Aigis_r.exe，被动记录官服自然返回的响应：不主动发请求，不点击，不改内存。写盘的只有游戏进程内已去掉凭据的业务数据。

同时采公共主表、资源版本并导出 70/71 调度配对时，用 [官服一键采集](capture-all.md)：先运行 `client/capture-all.ps1 -Mode Check`，再运行 `client/capture-all.ps1 -Mode Wait -Timeout 7200`，随后从 DMM 手动启动新的原版。一键入口使用本采集器的 `All` 范围，保留以下过滤与排除规则；结束时 Ctrl+C 协作收尾，`run.json` 分别报告三个分项。该编排尚未实机验证。

## 用法

```powershell
.\client\capture-responses.ps1 -Mode Check -Preset summon
.\client\capture-responses.ps1 -Mode Wait -Preset battle
.\client\capture-responses.ps1 -Mode Wait -Operations 41,39
.\client\capture-responses.ps1 -Mode Wait -All -Timeout 7200
```

`-Mode Check` 只核对原版指纹与挂点，不附加进程；`-Mode Wait` 等原版启动后附加；`-Mode Pid -ProcessId <PID>` 附加到已在运行、路径与 SHA256 都匹配的原版。采集范围三选一：

- `-Operations`：列出注册号，每个号至少采到一次后自动结束。
- `-Preset`：用下表的预设号表，同样采齐即结束。
- `-All`：采所有未排除的响应，到时限、按 Ctrl+C 或关闭游戏时正常结束。获准新号的被动采样（CAP-03）用这一项。

| 预设 | 注册号 | 对应条目 |
|---|---|---|
| `summon` | 12、13、35、108 | CAP-01、CAP-02 |
| `battle` | 66、67、68、76、77、78、80、81、82、83、116、130、143 | CAP-06、CAP-09、CAP-10、CAP-11、WD-07、RN-26 |
| `login` | 35、115、116 | CAP-07 的 DailyGift、CAP-08、RN-26 |
| `shop` | 46 | CAP-07 |
| `card-status` | 9、51、76、100、101、149 | RN-24 |

预设定义在 `aigis_ps.response_capture.RESPONSE_PRESETS`。时限默认 1800 秒，最长 14400 秒，含等待原版启动的时间；到期时已送达的响应照常处理，之后到达的不再延长采集。

本采集器单独运行时只记录响应，不保证 70/71 同轮配对。只采召唤调度可用 `capture-schedule.ps1`；一键入口则从本轮响应中导出首份完整配对，拒收新的 70 时清除旧候选。两种方式都不能把仅出现两个注册号当作完整调度。

## 排除的接口

无论选哪种范围，以下接口一律不采：

| 类别 | 注册号 |
|---|---|
| 方法密钥 | 31 |
| 登录与令牌 | 152、153 |
| 账号联动 | 144、145、146 |
| 兑换码 | 32 |
| 外链表（链接里可能带账号参数） | 45 |
| 付费 | 47、50、91、154、155、156 |
| 反作弊 | 102、103 |

注册号和请求类虚表两项任一命中即排除，不读响应正文，只在 `excluded_seen` 里记次数。46 的礼包目录不在排除之列。`-Operations` 里写了排除号会直接报错。

## 去凭据规则

过滤在游戏进程内完成，宿主收到的已是过滤结果：

- 凭据名节点整枝删除。判定看标签名和 N 属性，取 `[` 之前的部分，不分大小写，忽略 `_`、`.`、`-`。凭据名包括 SYSTEM、UI/UK/MK、GPVI/GPOT、各类 token/session/cookie/password，以及 ExchangeKey。
- LGI 组不论在哪一层，都删除 A2/A6/A10（玩家ID）和 A7（UK）。
- 首列为字符串 A1 的键值表（如 PGP2）：A1 的键名是凭据名时，删掉这一行，所有列同步删除；列长不齐时整组删除。
- 注释、XML 声明和元素间空白不保留。其余组、值、CDATA 和实体原样保留。

Python 端按同一套规则重新解析、复核。过滤结果与收到的报文不一致时，该条记为 `response_agent_filter_incomplete` 拒收，不写盘，采集继续。结构不合 AL XML 的响应只记注册号和固定拒收码；非 XML 的响应（如 `0,0`）也一样。

## 挂点

一共 8 个响应入口：默认消费函数 A801D0，以及 7 个加载类的专用消费函数（注册号 34、35、36、38、39、41、43/44）。8 个入口都从 A80530 里 A80608 的同一调用点进入，返回地址都是 A8060A。

每次调用依次核对：返回地址；请求对象虚表的 +0x58 是否指向本入口；+0x6C 的注册号。三项都过了才读响应字符串。加载类入口还要求虚表必须是对应的加载类。

附加前核对以下各项，任何一处不符就退出，不会退回全抓：
- exe 指纹；
- 响应管线的代码块；
- 8 个入口的序言；
- 7 个加载类和 15 个排除类的虚表槽位。

大响应（如 41 全部单位）在游戏网络线程里过滤，可能短暂卡顿。

## 输出

结果在 `runtime/response-captures/responses-时间-PID-随机值/`：

- `NNNNN-注册号.xml`：过滤后的响应，序号按到达顺序。
- `records.jsonl`：每条响应一行，记录以下内容：
  - 注册号、入口、虚表；
  - 删掉了哪些凭据；
  - 各组的列数和行数；
  - `alxml_loadable`，即严格 AL XML 解析能否读入。读不入的照样保存。
- `state.json` 记录进度，`manifest.json` 记录结束状态。

| 状态 | 含义 |
|---|---|
| `complete` | 选定的号全部采到 |
| `stopped` | `-All` 正常结束 |
| `partial` | 中途出错或没采齐，已采数据保留 |
| `failed` | 一条也没有 |

结束原因写在 `end_reason`。单次最多 8192 条、合计 1 GiB，超出以 `response_capture_capacity` 结束；代理消息超出本地队列容量时以 `response_queue_overflow` 结束。

`All` 的 `stopped` 只说明采集正常结束，不代表 22 条采集与验收任务已完成。实际覆盖取决于账号、日期、活动和手动访问的页面；打开召唤菜单与商店目录不会自动产生抽卡或购买响应。

文件里是账号的业务状态（单位、持有物、进度），凭据已经去掉，但不要外传。所有输出都留在 111 项目内。

## 范围与验证

- 不采请求正文。WD-06 的控件名靠实机点击、对照本地服务端日志来定。
- 7 个加载类入口只做了静态核对，还没有实机采集验证。
- 去凭据规则、宿主流程、Node 隔离环境里的挂点脚本共 112 项定向测试，其中 JS 与 Python 两套过滤规则逐例对照。这些测试不能代替真实采集验收。
